# R01：对峙与反攻

目标：交付可反复重置的 Windows 试玩场景，让玩家看懂对峙猫的扑击，并用侧移、猫扑或 Q 做出不同反应。每次重置验证一段短对抗，连续试玩约 3–5 分钟；不通过堆高敌人生命强行延长单次对抗。

只做：一个空旷房间、圆头猫玩家、老吴叫、杂兵、对峙猫、Space 猫扑、Q 哈气、最小 HUD、重置与测试开关。暂不做购物、鱼干、升级、回血、Boss、存档、音乐分层或复杂敌人调度。

## 交付位置

- Unity 工程：`Game/`，目标 Unity 6.3 LTS；场景 `Game/Assets/Hachimi/Scenes/R01_Combat.unity`。
- 程序与配置：`Game/Assets/Hachimi/Scripts/`、`Game/Assets/Hachimi/Settings/`；一个可在 Inspector 调整的配置即可。
- 素材原件：`SourceAssets/Art/R01/`、`SourceAssets/Audio/R01/`；程序导入 `Game/Assets/Hachimi/Art/`、`Audio/`。
- 构建：`Builds/R01/Windows/`，含启动程序及完整依赖文件；交付记录注明实际启动文件名。

上述目录由对应执行任务创建，目前均未交付。程序先用简单几何占位，不等美术／音频。

## 起始配置

采用 Unity 世界单位，俯视 XY 平面；距离默认按中心计算，实际伤害使用形状相交。以下为起跑值，允许试玩调参并记录修改原因，不是已经验证的平衡值。

| 项 | 初值 |
| --- | --- |
| 场地／玩家 | 可走矩形 18×10；玩家半径 0.35，生命 100，移速 4.5 单位／秒 |
| 猫扑 | 距离 2.4，时长及免伤 0.18 秒，冷却 3 秒；穿敌不穿墙，静止沿最后移动方向 |
| 老吴叫 | 射程 6，声波宽 0.5、速度 12、单波伤害 8；一轮两道、间隔 0.1 秒；起手 0.12 秒，每轮开始间隔 1 秒 |
| 对峙猫 | 半径 0.45，生命 64，移速 2；距离玩家不超过 3.4 时尝试预警；观察 0.3 秒＋锁向 0.5 秒 |
| 敌扑 | 长度 4、宽度 0.8、速度 10，途中只伤害玩家一次、伤害 20；随后恢复 0.8 秒再接近／预警 |
| 杂兵 | 半径 0.3，生命 16，移速 1.6，接触伤害 8；自身攻击间隔 0.8 秒，共享玩家受伤保护 |
| 哈气 | 满值 100，半径 3.5；不附带基础伤害，杂兵推开 1 单位；强化 6 秒，攻速 +30%、射程 +15% |
| 打断 | Q 仅取消观察／最终锁向预警；原地“已老实”1.2 秒、承伤 +25%；老吴下一轮剩余等待压至最多 0.15 秒，已发攻击不改向 |
| 受伤保护／充能 | 玩家受伤后 0.5 秒免伤；有效伤害×0.07＋击杀×1 充能，强化中不充能 |

老吴首轮普通击退暂为 0；另设测试按钮施加 0.5 单位普通击退，检查锁向例外，不为测规则额外制作一把武器。猫扑和敌扑用连续路径检测或等效方式避免高速穿过目标而漏判。

敌人最终锁向时固定起点、方向与墙体截断后的覆盖；清除普通击退余速。最终预警和攻击有效段不受普通击退，仍正常承伤；Q 不可中断已经扑出的敌人。对峙猫只有扑击有效段伤人，其他状态身体接触不伤人。

## 两个可重置预设

1. **单猫对峙（默认）**：玩家 `(0,0)`，对峙猫 `(3.2,0)`，Q 满、猫扑就绪。敌人入场提示 0.6 秒后才行动，玩家可立即操作和攻击；无人为保命或强制免死。
2. **低密度混编**：同一只对峙猫，加三只杂兵，出生位置固定在玩家 3 单位外、不叠放。清空即结束，不自动无限补怪；用于观察穿透和转火。

两者均可用调试面板切换满／零 Q、猫扑就绪／冷却、自动攻击开关、选敌模式、必要碰撞与预警显示、装饰反馈开关。设置后按 R 重置，保持当前所选测试选项；生命、敌人、弹丸、技能、计时与选敌全部重建。死亡或清空后仍可 R 重试，Esc 暂停与恢复。

选敌 A 沿用[方向优先规则](../../Docs/Design/Player_Combat.md)；选敌 B 为“打断目标 → 有效当前目标 → 最近目标”。相同场景与数值对照，场景角落标明当前模式。调试功能仅放可收起的小面板，不挤占基本按键提示。

## 本轮 review 只回答四件事

- 预警是否与伤害一致，锁向后击退和 Q 是否符合状态规则？
- 普通侧移／猫扑能否躲开；成功 Q 后是否在窗口内实际命中对峙猫？
- 撤退和横移时，哪种选敌更符合玩家意图？
- 开启基本猫表情与声音后，是否更容易认出动作、读懂危险？

自然充能的完整三波节奏、贴墙长期收益和 Boss 构筑兼容性留到相应玩法存在时测，本轮不假装已经覆盖。基本测试与交付记录写在 P03；review 后再决定下一轮内容。
