## 实际验证安排

先跑战斗，不等美术完成。下面是实现后要做的检查，目前不标记为已通过。

| 试验 | 做法 | 要记录的结果 |
| --- | --- | --- |
| 同一对峙的三种处理 | 分别横移诱导、猫扑、Q 打断，重复相同配置 | 是否受伤；是否留下输出位置；打断后首发是否命中对峙猫 |
| 状态可信度 | 玩家贴近预警、扑击、舔爪、被打断状态；锁向前后施加普通击退及 Q；低帧率再重复 | 提示与真实覆盖是否一致；Q 是否只在允许状态取消招式；同招是否重复扣血 |
| 无技能逃生 | 墙角、混入杂兵与短寿命远程弹；猫扑冷却、Q 空 | 受伤前是否存在可见、可达的普通移动路线 |
| 选敌对照 | 当前方向优先规则与简化规则交替；包含向后撤退、横向绕行、短促变向、打断后旁边出现新杂兵 | 实际转火与玩家期待是否相符；区分错误转火和难以接近想打的目标 |
| 正常局哈气节奏 | 零能量开局，跑完三波；另测不携带老吴叫的配置 | 每波首次满值时刻、满后等待时间、释放是否成功打断／仅强化、打断后首个有效命中时间；区分主动等机会与波尾不值得释放 |
| 墙边策略对照 | 相同装备和出怪安排分别中央活动与沿墙移动，允许场地调度按现有规则响应 | 受伤、击杀收入、特殊攻击数量及操作变化；既查无解围堵，也查贴墙是否长期低代价占优 |
| AI 对照 | 相近数量、血量和伤害下比较纯追击与战术行为 | 多出来的是诱导、切入、变向，还是只能慌乱逃跑 |
| 反馈对照 | 同场景基础反馈／完整反馈；包含高攻速高暴击 | 重击满足感、危险识别、死因理解和连续停顿情况 |
| 构筑对照 | 等价预算预设穿线、贴脸、连射与混搭装备；分别打敌群与纯单体 Boss | 走位变化、击败时间与有效输出窗口；回音额外命中／伤害／击杀，而非仅触发次数 |
| 商店与随机 | 先模拟多组商品序列，再看真实购物选择 | 第 3／6／9 波装备、刷新支出、关键商品可得性、转型机会 |
| 跨波恢复 | 同一存档状态商店等 0 秒与 60 秒，再进入下一波 | 生命、Q、口香糖状态一致；没有等待获益 |
| 无恢复生存 | 不携带口香糖时购买厚肚皮，再玩正常波；与有口香糖局比较 | 已损失生命量是否保持；厚肚皮是否立即提高承伤余量；没有恢复道具的局是否仍可合理完成 |
| 波末与购买边界 | 同步死亡／计时结束；Boss 同归于尽；满槽取消替换；快速连点 | 结果唯一且符合规则，没有重复奖励、误购或丢失装备 |
| 早期性能 | 第二阶段用占位资产在独立构建运行峰值战斗 | 帧时间、卡顿来源、实际对象数量和测试机器 |

性能目标沿用：1080p，参考 i5-10400／GTX 1650／16 GB，目标 60 FPS；压力组合约 120–150 敌人、250 弹丸、200 拾取物。它们是待测负载，不是已经达到的配置要求。没有对应硬件时报告实际测试机器，不推断参考机器必然达标。

邀请 5–8 位简中玩家各玩 2–3 局，尽量交换对照顺序，避免所有人都先玩简单版。记录是否认出梗、能否解释一次死因、购买理由，以及是否自发提出“再来一局换种武器”或“下次留 Q 打断”。这些是设计信号，不是留存率或市场规模结论。
