**3. 核心循环、操作与成长**

每波自动攻击与走位 → 击杀并收集鱼干 → 波次结束 → 用鱼干购买武器、升级与道具 → 进入更复杂的敌人组合 → 击败最终 Boss。

| 输入 | 行为 | 设计目的 |
| --- | --- | --- |
| WASD | 移动 | 绕敌、穿插、收集、接近高威胁目标 |
| 自动攻击 | 各武器按射程选择目标 | 让注意力主要落在走位和局势上 |
| 空格 | 猫扑 | 短距离位移，带短暂无敌，初始冷却约 3 秒 |
| Q | 哈气 | 哈气值满后主动爆发，震退杂兵、打断可中断的对峙动作并强化攻击 |
| 鼠标 | 选择、购买、查看比较 | 商店以少量高信息密度卡片完成决策 |
| Esc | 暂停 | 暂停战斗并打开设置 |

猫扑的起步调参值：位移约 0.18 秒，前 0.12 秒无敌；无方向输入时沿最后移动方向。落点仍受场地边界约束。它应能穿出一次包夹，但冷却期间仍需要正常走位。

哈气值由有效伤害与击杀积累，Boss 战也能充能。满值可留到下一波；商店阶段不能释放。目标是常规战斗约每 40–60 秒获得一次机会，实际按试玩调整。猫咪头像从常态逐渐变成飞机耳、炸毛表情，满值显示“哈气！[Q]”。

哈气起步效果：按 Q 发出短促嘶声与一次近身气浪，造成少量伤害、击退杂兵，并打断应激对峙猫正在预告的扑击；之后进入 6 秒的哈气强化，攻速提高约 30%，攻击范围提高约 15%。被打断的对峙猫后退约 0.8 秒，显示一次“已老实”，玩家可以借机切入。Boss 的强攻击保持原有时序，使用加粗预警形状提示；哈气仍造成伤害并强化玩家，但不会让 Boss 连续失去行动。

哈气期间猫咪压低身体、耳朵后翻，轮廓和攻击纹理增强；角色继续正常移动和猫扑。视觉夸张集中在猫脸、喷气与攻击轨迹上。哈气结束后短暂切回“暂时老实”的表情，HUD 回到积攒状态。

鱼干是唯一购物货币，波内成长由拾取、输出和能量积累构成，主要装备决策放在波间。玩家升级不会在密集战斗中反复弹窗。

商店每次展示 4 个商品，支持购买、刷新、锁定、出售与数值对比。再次购买已装备的同种武器会提升等级，最高 3 级；每种武器只占一个装备槽。武器升级首先提高现有数值，便于控制首版制作量。基础道具允许有限叠加，机制道具每种限购一次。

早期商店提高已有武器与相关道具的出现权重，并保持跨流派选择。经济目标是每波能做出约 1–2 次有效购买；具体掉落和价格在完整流程可玩后一起调整。

12 个被动道具起始池：尖尖爪（伤害）、曼波节拍器（攻速）、厚肚皮（生命）、小跑鞋（移速）、星星眼（暴击）、自动吸附（拾取范围）；回音罐（老吴叫周期性追加弱声波，短“内个”声点缀）、猫薄荷（延长哈气）、不倒翁（增强环绕击退）、大狗叫（哈气时追加一次伤害声波）、备用纸箱（每波提供一次护盾）、嚼口香糖（脱离受击后缓慢恢复生命）。

嚼口香糖恢复的起步规则：持有道具且生命未满，连续约 4 秒未受伤后开始嚼嚼，每秒恢复约 2% 最大生命，最多持续 3 秒，触发后进入约 12 秒冷却；受到新伤害时结束本次恢复。数值后续按试玩调整。嘴部循环配绿色小加号，既能读出恢复，也能认出“嚼口香糖回血”。玩家可以继续移动和攻击，主动寻找恢复窗口。

自动吸附只增强物品收集，不替玩家移动。曼波节拍器的攻速加成由普通属性系统计算；音乐拍点只影响装饰动画，不改变判定与冷却。

| 老吴震场 | 老吴叫 + 拍地板 + 回音罐 | 用哈气打断对峙，随后以穿透声波和拍地重击打开正面 |
| 炸毛贴脸 | OIIA 转盘 + 猫爪连拍 + 不倒翁 | 沿敌群边缘切入，用哈气与环绕击退维持近身空间 |
| 南北绿豆连射 | 南北绿豆 + 曼波节拍器 + 嚼口香糖 | 用高频三连弹和末发击退保持距离，主动走位获得嚼嚼恢复窗口 |

这些是装备之间自然形成的搭配；首版不再增加独立套装系统。每把武器至少在攻击形状、节奏或站位需求上有一个明显差异。

**5. 聪明敌人：可读的战术与可利用的破绽**

大多数敌人提供清场与击退的满足感，少量战术敌人改变局面。常规波次先将同时在场的战术单位控制在 3–5 个，避免玩家持续被特殊攻击压制。

| 敌人 | 行为 | 玩家看见的提示 | 玩家如何应对 |
| --- | --- | --- | --- |
| 围观杂兵 | 直接追击，同时与邻居保持少量间距 | 动作简单，轮廓小 | 走位聚怪并成片清理 |
| 截路猫 | 根据玩家近期移动方向前往前方拦截点 | 身体侧倾、奔跑拖尾 | 突然转向，利用它重新判断的间隔 |
| 应激对峙猫 | 接近后站立对峙；早期观察玩家，随后锁向扑击；若玩家在早期拉远则短暂后撤 | 约 0.8 秒站直、抬爪、嚼嘴和短“老吴”叫，地面箭头同步收束 | 在观察期诱导方向，再侧闪；或用哈气打断，趁约 0.8 秒后退反攻 |
| 吐槽猫 | 保持射程，分段后退，停下发射低速弹 | 嘴部蓄力、清晰弹道 | 利用射击停顿近身，避免一直绕外围 |
| 指挥猫 | 给附近少量杂兵分配左右接近位置 | 一次短叫阵和抬爪号令，受指挥单位出现小标识 | 绕侧接近指挥猫，打散协作 |

精英复用对峙猫的主体，增加体型、配饰与一次连续扑击。连续攻击之间仍保留预警。Boss“纸箱暴君”使用两种核心招式：扇形拍击与直线翻滚；半血时站起、炸毛、嚼嘴并长叫一声“老吴”，随后改变两招的组合，在连招结束后露出明显攻击窗口。普通战术敌人的部分攻击后空隙表现为“舔爪程序覆盖”：突然抬爪舔毛，向玩家明确暴露反打时机，时长仍由原有招式恢复状态决定。

对峙猫的 0.8 秒预告初步分为约 0.3 秒观察与 0.5 秒锁向；站姿、嘴部和声音叠加在同一次预告中。玩家始终可以自由移动、攻击、猫扑和哈气。敌人表现得犹豫、叫阵或退缩，同时这些动作给出明确的反制机会。

关键规则：预判只使用已发生的位移，截路预测距离有限；扑击锁定后不能持续追踪玩家转向。远程敌人后退有间隔，不能永远保持理想距离。同一时段先限制为最多两个明显特殊攻击，组合预警要留出可辨认的逃生方向。敌人伤害同时使用地面形状和动作提示表达。

实现采用小型状态机、局部避让、有限运动预测，以及一个管理出场组合和特殊攻击名额的调度器。指挥行为先实现为少数单位的站位分配。敌人不需要训练模型或接入在线大语言模型；这里的“AI”是可调、能实时运行的游戏行为逻辑。

**6. 战斗动效、镜头、声音与 UI**

反馈分为普通命中、重击或暴击、击杀、玩家受伤、哈气五个层级。普通攻击有清楚触感，重击保留更强表现空间。

| 事件 | 动效与声音设计 | 初始控制原则 |
| --- | --- | --- |
| 普通命中 | 敌人短闪、局部压扁、方向性击退、轻音效 | 优先发生在受击对象上，保持场景稳定 |
| 重击／暴击 | 更强形变、较粗特效、低频重音、短促震动 | 极短停顿约 25–40 毫秒，合并同一瞬间的重复请求 |
| 击杀 | 侧向弹飞或缩小、少量碎屑、鱼干弹出 | 快速让出视野；密集音效限制同类同时播放数量 |
| 玩家受伤 | 猫脸变化、短暂边缘提示、清楚的受击声 | 让伤害来源和剩余血量容易读到 |
| 哈气 | 飞机耳、短促嘶声、近身气浪、炸毛轮廓和攻击拖尾 | 强反馈集中在开始和结束，中段保持敌人预警清晰 |
| 对峙与嚼嚼 | 猫身体突然站直，前爪抬起，嘴部小幅循环；被哈气打断时缩身后退 | 姿态与地面预告同步，不延长或隐藏攻击判定 |
| 商店购买 | 卡片轻回弹、图标飞入槽位、钱币变化、短确认音 | 约 0.12–0.20 秒，连续操作及时响应 |

全局停顿仅用于低频重击，并限制触发频率；普通命中依靠局部动作。UI 与输入使用独立于战斗停顿的时间更新。镜头震动、闪烁和粒子数量提供可调强度，关闭后仍能依靠动作、轮廓和音效读懂战况。

HUD 布局：左上固定血量与受击方向提示，顶部中央显示波次和倒计时，右上显示鱼干，左下显示 4 个武器槽，底部中央显示猫扑冷却与哈气值。战斗区域中央留给角色、敌人和预警。哈气值保持数值与状态图标清楚；“飞机耳了”“哈气！[Q]”等短句作为补充，重要敌人被打断时才出现一次“已老实”。

商店卡片首先显示“这是什么、会改变什么、多少钱”，属性变化用数值与箭头共同表达。猫梗短句放在次级区域。结算展示最终装备、造成伤害最多的武器、击杀数及死因，并提供一键再来。

所有正文、价格、血量和按钮标签都使用 Unity 实时文本组件。AI 用于图标、边框装饰和风格参考；最终界面由可复用组件搭建，便于修改数值、适配分辨率和播放动画。

声音区分三种识别特征：哈气是短促嘶声，老吴叫是有起伏的拖长声，嚼口香糖是小音量的节奏性嘴部声。完整老吴长叫在初次展示、重要强化和 Boss 演出时播放，持续攻击改用短采样与声波音；回音罐可用“内个”短声表示追加攻击。商店进入或刷新用一次“叮咚鸡”提示；大狗叫道具只在哈气触发时突出一次。敌人预警与玩家受伤声优先，梗音频可单独调低或关闭。

音乐采用两条基础曲目：原创哈基米式战斗曲、原创商店与结算曲。战斗曲使用基础伴奏、短人声、强化重拍三个播放层：平时伴奏清楚，哈气时加入猫声和重拍，结束后淡出。哈基米、南北绿豆、曼波等短音节提供识别线索，旋律由本作原创。现有《蓝莲哈》《跳楼基》《往事只能哈基》《约德尔曼波》《哈雪大帽险》等用于试听参考，样本及来源见梗参考库。

角色轻微律动、拾取和 UI 装饰可以跟随拍点，攻击、伤害、猫扑和哈气始终立即响应。哈气的嘶声与气浪立即出现，音乐层随后在合适拍点加入。必要预警与梗人声分别混音，降低音乐或梗音量仍能读懂战斗。

**7. 单人开发的 AI 素材方案**

推荐美术方向：**统一重绘的猫咪表情贴纸 + 简洁俯视客厅 + 有弹性的程序动画。** 角色面向镜头，按移动方向左右镜像；用脚底阴影建立位置感。颜色先使用奶油白、深灰和少量鲜艳点缀，敌人预警采用稳定的高对比色与形状。

选择这种形式的理由是：猫梗依靠轮廓与表情就能被识别，静态图可以通过挤压、旋转、位移和嘴部替换获得生动表现，连续帧的一致性工作量较低。单人主要投入在挑选、调整和集成上。

| 资产类型 | AI 主要负责 | Unity／程序负责 | 开发者负责 |
| --- | --- | --- | --- |
| 猫与敌人 | 基础形象、表情变体、站立姿态、配饰 | 左右镜像、挤压回弹、嚼嘴、耳朵转动、受击和旋转 | 选择一致的结果，检查缩小后的辨识度 |
| 武器和道具 | 独立透明底图标、局部贴图 | 挂载位置、运动轨迹、碰撞与数值 | 检查含义是否容易识别 |
| 场景 | 地面纹理、少量家具、纸箱与装饰 | 重复铺设、排序、碰撞和阴影 | 控制背景复杂度与可行走区域 |
| UI | 视觉参考、头像、装饰图标 | 排版、文本、卡片、状态和动效 | 检查信息优先级及操作手感 |
| VFX | 少量爪痕、星星、冲击等纹理 | 粒子、拖尾、颜色、持续时间和层级 | 检查是否挡住敌人攻击 |
| 音频 | 短音效候选与循环音乐候选 | 分层、混音、变调、触发和循环 | 试听、选材、调整响度与重复感 |

素材生产顺序：优先以圆头耄耋为小样角色，生成数个风格候选，选出一张参考母版；随后生成常态、受击、哈气表情和嘴部局部图，再以相同视角和用色扩展敌人、站立姿态及图标。第一批就同时检查圆头轮廓、飞机耳、嚼嘴、老吴张嘴和站立对峙的辨识度，及时放进游戏查看。

第一轮就把猫、一个敌人和一把武器导入 Unity，观察在 1080p 游戏画面中约 48–96 像素大小时是否仍然可读。原图漂亮只代表候选合格，场景中的识别与动画表现才决定是否采用。

角色优先拆成身体、表情、武器三个视觉部分，在表情中叠加嘴部和耳朵。两张嘴型循环制作嚼嚼，嘴部放大和身体前探制作老吴长叫；耳朵转动、炸毛轮廓与喷气纹理制作哈气。应激对峙猫和 Boss 各补一张站立姿态，用上下位移与轻微摆动连接前后动作。主体动画先用位置、角度与缩放制作；攻击与受伤共享模板。角色根节点保存移动与碰撞，视觉子节点播放夸张变形，避免站起或猫脸变形同时改变受击范围。第二阶段按实际需要给少量主体加入简单骨骼。

输出整理包括透明底边缘、裁切留白、统一尺寸、朝向和轴心；这部分可以用工具与脚本辅助，但仍需在引擎里查看。连续动作依靠程序驱动，角色表情通过少数静态图切换。

素材规模预计为 **55–70 份最终采用的静态资源**：约 20 份角色、敌人、嘴部与站立状态素材，18 份武器和道具图标，12 份地面与环境素材，8 份 UI 装饰，8 份共享特效纹理。头像和嘴部尽量复用，精英以普通敌人加配饰制作。生成候选和返工次数另计。

音频控制在约 20–30 个短音效和 2 条基础音乐素材。优先制作哈气、老吴长短版、嚼嚼、拍地、曼波、叮咚鸡、大狗叫及短人声点缀，通过变调与分层扩展听感。AI 先生成纯伴奏候选，再单独制作干净人声和猫叫，按选定节拍排布，检查循环接缝与响度；不依赖一次生成即可得到整曲和分轨。第一周进行图片与音频的实际导出、整理和导入试验，猫叫与音乐使用原创表演、合成或 AI 生成的可用结果。

AI 预算先用一小批实际素材估算：记录生成成本、最终采用数量和整理耗时，得到“每份可用素材的成本与时间”后，再估算剩余批量。订阅额度与导出条件随选用工具确认。素材目录保留参考图、生成记录和采用结果，便于继续做同风格内容；公开发布前确认使用素材与所选生成工具的使用条件。

**8. Unity 实现方案与性能目标**

建议使用 **Unity 6.3 LTS + URP 2D Renderer**。这是为了本项目的制作周期与工具一致性作出的选择；官方目前列出 6.3 LTS 的支持期限至 2027 年 12 月。具体补丁版本在创建项目时确定，并正常记录在 Unity 项目中。[Unity 版本与支持](https://unity.com/releases/unity-6/support)

| 部分 | 方案 | 作用 |
| --- | --- | --- |
| 2D 画面 | Sprite、URP 2D、少量灯光、粒子与简单材质 | 实现贴纸主体、命中高亮和局部光效 |
| 操作 | Input System | 管理移动、猫扑、哈气和界面输入 |
| UI | uGUI + TextMeshPro | 卡片、HUD、中文文本、数字与动效 |
| 镜头 | 正交相机，按需加入 Cinemachine | 小幅跟随、战斗震动和 Boss 演出 |
| 内容配置 | ScriptableObject | 武器、道具、角色、敌人与波次的配置 |
| 移动与碰撞 | 2D 碰撞与触发器，视觉和碰撞分离 | 调整移动手感、命中及局部避让 |
| 敌人行为 | 小型状态机、局部避让、特殊攻击调度 | 截路、扑击、站距及协作 |
| 高频对象 | 对象池、邻域查询、图集 | 减少反复创建销毁与不必要搜索 |
| 本地数据 | 设置与最佳成绩的小型存档 | 支持下次打开与快速重试 |

Unity 官方提供 URP 2D 光照、Input System 与 Cinemachine 的对应文档；表中具体组合是本项目的实现建议。[URP 2D 光照](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/2d-index.html)、[Input System](https://docs.unity3d.com/6000.3/Documentation/Manual/com.unity.inputsystem.html)、[Cinemachine](https://docs.unity3d.com/6000.3/Documentation/Manual/com.unity.cinemachine.html)

代码按局流程、战斗、敌人行为、内容配置、表现和 UI 划分职责，使用普通组件及清楚的数据流。先完成可玩的敌人与攻击，再按实际瓶颈决定是否加入更复杂技术。

地图主战区保持开阔，家具主要放在边缘。可破坏纸箱先作为不阻挡移动的掉落物容器，因此首版的寻路需求集中在局部避让和角色间距。

AI 决策可先按每秒 5–10 次错帧更新，移动和碰撞正常更新；蓄力锁向、命中等关键时刻按实际战斗时序处理。敌人、子弹、鱼干和粒子使用对象池；同类浮字和音效合并或限量。

暂定性能测试档位：Windows，i5-10400 / GTX 1650 / 16 GB，1920×1080；第一周根据实际可用设备调整并记录型号。目标场景为同屏约 120–150 个敌人、250 个投射物、200 个拾取物及正常特效，目标稳定接近 60 FPS。这是待实测目标，不能由组件选择直接保证。

在独立构建中记录帧耗时分布、卡顿和内存趋势；持续运行多个完整回合，尤其检查哈气、Boss 与集中掉落。发现问题时按 Profiler 结果调整碰撞、查询、透明特效和动态对象数量。

**9. 波次节奏与第一局示例**

| 波次 | 战斗时间目标 | 主要体验 |
| --- | --- | --- |
| 1–3 | 每波约 45 秒 | 圆头耄耋伴随哈基米式音乐入场，使用老吴叫；首次商店出现南北绿豆与嚼口香糖；认识对峙猫、截路猫及哈气反制 |
| 4–6 | 每波约 55 秒 | 哈气与装备配合形成明显优势，引入远程敌人与第 5 波精英 |
| 7–9 | 每波约 60 秒 | 构筑基本成形，敌人混编与指挥猫促使主动切入 |
| 10 | Boss 预计 90–120 秒 | 通过两个阶段检验构筑与闪避，击败后通关 |

Boss 战计时用于统计，不设到时直接失败。普通波次以存活到结束为目标；波末收尾回收剩余鱼干并进入商店，避免追逐最后一只杂兵。角色生命归零立即结束本局。

按以上配置，战斗约 9.5–10 分钟，加上 9 次各约 20–30 秒的购物，典型一局约 12–15 分钟。玩家慢慢阅读商店时可以更长。

一局预期片段：菜单中的圆头耄耋翻出飞机耳，短人声与音乐一起出现。开局用一次“准备好应激了吗，基米们”的短提示，随后老吴声波打穿杂兵；前方猫突然站起、抬爪、嚼嘴叫阵，玩家在箭头收束时按 Q 哈气，对峙猫后退并冒出“已老实”。第一次商店用“叮咚鸡”短声迎接，玩家拿到南北绿豆和嚼口香糖。之后用三连豆弹击退截路敌人，猫扑换边，争取几秒未受伤的空间开始嚼嚼回血。Boss 半血站起长叫时，玩家按加粗预警侧闪，在其连招结束后的空隙用哈气强化老吴声波，音乐同步进入更强的一层。

**10. 单人开发排期**

估算前提：开发者具备基本 Unity 与 C# 经验，每周可投入约 30 小时，使用 AI 辅助代码及资产制作。完整 v0.1 预计 **240–300 小时，约 8–10 周**，其中包含 40–60 小时的素材返工、调参和排期缓冲。若从零学习 Unity，时间需要另加。

| 阶段 | 工作量估算 | 可直接试玩或查看的交付 |
| --- | --- | --- |
| 1. 基础可玩循环 | 25–30 小时 | 移动、自动攻击、伤害、死亡、重开、基础波次；同时完成首批图片和音频导入试验 |
| 2. 手感与美术小样 | 35–40 小时 | 圆头耄耋、老吴叫、南北绿豆、嚼口香糖道具、对峙猫、猫扑与哈气打断、基础猫声音乐、3 波商店循环 |
| 3. 构筑与完整流程 | 35–40 小时 | 6 把武器、12 个道具、购买升级、10 波与结算界面 |
| 4. 战术敌人与 Boss | 40–50 小时 | 5 种敌人、精英、Boss、混编出场、预警与攻击窗口 |
| 5. 资产与 UI 完成 | 35–45 小时 | 第二角色、其余 AI 素材、中文梗 UI、两条基础曲及战斗音乐分层、动态反馈与选项 |
| 6. 试玩与优化 | 30–35 小时 | 平衡调整、性能记录、问题修复、Windows 测试包及试玩说明 |
| 返工与缓冲 | 40–60 小时 | 处理素材不一致、玩法修改和集成问题 |

第一个月的主要成果应该已经是可反复游玩的版本。AI 素材从阶段 1 开始穿插制作，阶段 5 负责扩充与统一整理；阶段 3 的 Boss 波可以先用占位敌人跑通流程。

本次通过替换原武器、角色表现和道具，将中文梗纳入原有的 2 个角色、6 把武器、12 个道具与 5 种普通敌人额度。嚼口香糖按参考中的“嚼嚼回血”改为恢复道具，原弹丸武器位置交给南北绿豆；音乐短句、嘴部动画和界面提示共用已有组件。分层配乐、素材试听及新增恢复规则的工作安排在阶段 2、4、5 与既有缓冲内，完成小样后按实际工时修订估算。

开发时间紧张时，优先延后快乐哈基米、OIIA 转盘、香蕉回旋镖、四个次要道具、精英变体与额外装饰。保留圆头耄耋、老吴叫、南北绿豆、嚼口香糖、猫扑、哈气、应激对峙猫、商店、基础哈基米式音乐和一次完整 Boss 战，确保精简版也能体现中文哈基米主题。

**11. 试玩观察与 Demo 完成标准**

先邀请约 5–8 名玩家各玩 2–3 局，记录他们是否主动改变走位、是否能解释购买决定，以及死亡时是否知道发生了什么。样本用于发现问题与指导迭代，不作市场表现推断。

| 问题 | 验证方式 | 期望看到的现象 |
| --- | --- | --- |
| 上手是否自然 | 首局只提供简短按键提示，观察 60 秒 | 玩家能移动、猫扑、拾取并完成首次购物 |
| 攻击是否有力度 | 播放并实玩同一武器的普通命中与重击 | 玩家能分辨反馈层级，重击有明显满足感 |
| AI 是否改变决策 | 观察截路、扑击和远程混编时的走位 | 玩家出现转向、横闪和主动近身等不同应对 |
| AI 是否可理解 | 复看一次受伤或死亡片段 | 玩家能指出敌人的提示以及自己的反应机会 |
| 构筑是否成立 | 使用预设装备直接试玩三种组合，再观察随机局 | 三种打法均有完成普通难度的可能，操作方式有明显区别 |
| 哈气是否值得期待 | 观察哈气值满后的选择与释放前后战况 | 玩家愿意留到包围、对峙扑击或 Boss 攻击窗口使用 |
| 中文梗是否进入玩法 | 不先解释梗名，观察首屏、站姿、嚼嘴、长叫与哈气时的反应 | 玩家能认出圆头耄耋、老吴、音乐语汇等，并能解释嚼嚼恢复、声波或打断的作用 |
| 梗音频是否耐听 | 连续玩数局，并测试调低梗音频 | 长叫不会持续盖住战斗；音量降低后预警仍清楚 |
| AI 素材是否统一 | 在实际战斗尺寸下查看角色、图标与场景 | 猫梗可辨认，前景与背景分明，透明边缘干净 |
| 画面是否清楚 | 在特效密集时辨认血量、落点和危险方向 | 特效增强击杀感，同时保留必要战斗信息 |
| 性能是否够用 | 用记录了配置的机器运行独立构建 | 正常及峰值场景接近目标帧率，无持续内存增长 |
| 是否想重玩 | 结束后不提示，观察并询问下一局选择 | 能说出想尝试的另一个角色或武器组合 |

程序检查聚焦实际易错规则：武器升级效果、道具叠加、商店扣款、护盾与伤害、波次切换、死亡和重开后的状态。动作手感、AI 公平性与画面可读性依靠真实操作和回放判断。每周以可运行构建记录进展。

最终交付：Unity 源工程、可直接运行的 Windows Demo、采用的 AI 素材与生成记录、可编辑的内容配置、简短操作说明，以及试玩发现与后续调整清单。

**12. 第一轮实施顺序**

先在空场景中完成移动、自动攻击、受伤与重开，再加入 AI 重绘圆头耄耋、老吴张嘴与嚼嚼循环；接着实现老吴声波、南北绿豆三连弹、嚼口香糖恢复道具、杂兵及会站立预告的对峙猫，完成猫扑与 Q 哈气打断。补上基础原创猫声音乐、三波战斗和商店，得到形象、动作、台词与音乐都能被体验的第一版。

这一轮最重要的成果是一个短小但有手感的可玩样片：玩家能看出猫梗、感受到命中、读懂一次敌人攻击，并愿意再打一波。后续内容围绕这段体验扩展。
